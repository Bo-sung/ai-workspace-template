# 개발 로드맵

[← README로 돌아가기](../README.md)

> 본 로드맵은 **공방형 라인 디펜스 + 부대 카드 시스템 피봇** 기준으로 정렬된다. 전투 정체성/슬롯 운영/Phase 1 세부 범위는 [전투 코어](전투%20코어.md), [부대 카드 시스템](부대%20카드%20시스템.md), [Phase 1 구현 범위](Phase%201%20구현%20범위.md)를 따른다.

---

## 1. 개요

- Phase 1은 **재미 검증용 전투 프로토타입**이다.
- Phase 2는 **Vertical Slice** (전투 + 부대 카드 + 영지 + 아트의 한 줄기 슬라이스).
- Phase 3은 **MVP** (운영 가능한 최소 게임 형태).
- Phase 4는 **출시 준비** (밸런싱/최적화/QA + 결제·상점·운영 정책 확정).

각 Phase는 이전 Phase의 통과 기준을 충족했을 때 다음으로 넘어간다. 통과 여부는 [Phase 1 구현 범위 §5 성공 기준](Phase%201%20구현%20범위.md#5-성공-기준) 같은 명시 기준에 따른다.

---

## 2. Phase 1: 전투 프로토타입

### 2.1 목표

- 공방형 라인 디펜스 + 부대 카드 운용이 실제로 재미있는지 빠르게 확인한다.
- 수익화 / 소셜 / 복잡한 영지 운영은 **포함하지 않는다.**
- 본 단계의 성공 여부에 따라 Phase 2 확장, 피봇, 또는 폐기를 판단한다.

### 2.2 포함 범위

- **공방형 라인 디펜스 기본 전투**
  - 아군 / 적 본진 HP 및 본진 파괴 승패 처리
  - **지상 2라인 + 공중 1라인**
  - 적 출격 패턴(구 "웨이브" 재정의)
- **마나 시스템**
  - 초당 회복 / 최대 마나 / 소환 출격 비용 (수치 임시값)
- **부대 카드 5슬롯**
  - 슬롯 = 영웅 + 소환 유닛 묶음
  - 슬롯 메인 버튼으로 라인 출격
- **영웅 직접 출격 + 슬롯 비활성화**
  - 추가 소환 불가, 기출격 유닛 유지
  - 수동 귀환 / 전투불능 쿨다운 (임시값)
- **컨텐츠 분량**
  - 영웅 5명 / 소환 유닛 5종 / 적 5종 / 보스 1종 / 1챕터 5스테이지
- **간단 보상 / 평가**
  - 별 평가 기준 (본진 HP, 전투불능 여부, 클리어 시간 임시 기준)
- **임시 처리**
  - 플레이스홀더 아트
  - 로컬 / 더미 데이터 가능 (서버 없이 클라이언트 단독 진행 허용)
  - 한국어 단일

### 2.3 제외 범위 (Phase 1에서는 구현하지 않음)

- 가챠
- PvP
- 길드 / 친구
- 이벤트 / 이벤트 스테이지 / 시즌 패스
- 속성 상성 / 종족 상성
- 결제 / 상점
- Live2D / 일러스트 컷씬
- 강화 실패 / 옵션 재롤
- 복잡한 장비 세트 효과
- 방문 영웅 직구 / 모집권 직구 등 영입 결제
- **링크 시스템 정식화** (Phase 2 이관, Phase 1에서는 기초 링크 / 직접 출격 성능 반영만 테스트해도 됨)

> 영입 정책(제조 + 방문 영웅 + 가챠 병행 여부)은 결정하지 않는다. Phase 1은 **영웅 수동 부여**로 진행한다.

### 2.4 성공 기준

[Phase 1 구현 범위 §5](Phase%201%20구현%20범위.md#5-성공-기준)와 동일하다.

1. 전투 1판이 2~4분 내에 끝난다.
2. 유닛 소환과 영웅 직접 출격 사이에 의미 있는 선택을 느낀다.
3. 라인 하나가 밀리거나 뚫리는 상황이 시각적으로 보인다.
4. 5스테이지 중 최소 1회는 다른 전술이 요구된다.

## 3. Phase 2: Vertical Slice

### 3.1 목표

- 전투 + 부대 카드 + 최소 영지 + 아트가 한 줄기로 이어지는 **세로 슬라이스** 완성.
- Phase 1에서 검증된 전투 재미를 운영 가능한 형태로 다듬는다.

### 3.2 포함 범위

- **부대 카드 UX 개선**
  - 슬롯 / 영웅 출격 / 비활성화 / 쿨다운의 시각적 가독성 향상
  - 라인 출격 / 귀환 / 전투불능 피드백 일관화
- **링크 / 수리 시스템 정식화**
  - 링크 적용 범위는 Phase 1 권장안 검증 후 확정 ([영웅 시스템 §8](영웅%20시스템.md#8-링크-시스템과의-관계))
  - 수리 시스템: 전투 후 회복 사이클 도입
- **영지 기본 (3~4 시설)**
  - 자원 생산 / 마나 강화 / 육성·수리 연동 시설 중심
- **픽셀아트 1차 적용**
  - 영웅 / 소환 유닛 / 적 / 본진 / 라인 배경
- **컨텐츠 확장**
  - 영웅 10~15명
  - 소환 유닛 8~10종
  - 적 / 보스 추가 (수량은 Phase 2 시점 결정)
- **전투 밸런스 1차 조정**
  - 마나 / 본진 HP / 슬롯 쿨다운 / 영웅 출격 수치 1차 재조정

### 3.3 검증 기준 (후보)

- 전투 1판 시간 / 영웅 출격 선택 빈도 / 라인 압박 분포 같은 메트릭이 의도대로 나오는지 확인.
- 부대 카드 UX 변경 후에도 Phase 1의 성공 기준 4종이 유지되는지 재확인.
- 구체 KPI는 [KPI 지표](KPI%20지표.md) 작업에서 정렬.

## 4. Phase 3: MVP

### 4.1 목표

- 운영 가능한 최소 게임 형태로 통합.
- 영입 정책을 **결정한 뒤** 그에 맞는 영입 컨텐츠를 도입한다.

### 4.2 포함 범위

- **영입 / 수익화 정책 결정 후 반영**
  - 제조 + 방문 영웅 + 가챠 병행 여부 확정 → 정책에 맞춰 영입 시스템 구현
  - 주점 시스템(있을 경우)도 본 정책에 종속
- **전체 시스템 통합**
  - 전투 / 영지 / 수집 / 육성 / 수리 / 영입의 메타 루프 연결
- **컨텐츠 확장**
  - 20명 이상 영웅
  - 3챕터
- **일일 컨텐츠**
  - 일일 던전 (자원 / 육성 재료 회수 루프)
- **방어 전용 모드 후보**
  - 무한 방어전 등은 본 시점 이후 도입 여부 검토 (Phase 3 필수 아님, [§7 결정 필요](#7-결정-필요))

### 4.3 결정 필요 (Phase 3 진입 전)

- 영입 / 수익화 정책 (제조 + 방문 + 가챠 병행 여부)
- 본진 자동 공격 / 부속 시설 도입 여부 (구 "성벽 무기" 처리)
- 링크가 소환 유닛에도 적용되는지 (Phase 2 검증 결과 반영)
- 방어 전용 모드를 Phase 3에 포함시킬지, Phase 4 이후로 미룰지

---

## 5. Phase 4: 출시 준비

### 5.1 목표

- 출시 가능한 품질로 마감.
- 결제 / 상점 / 운영 정책을 확정해 실 운영 사이클을 시작할 수 있는 상태로 만든다.

### 5.2 포함 범위

- **컨텐츠 분량**
  - 30명 이상 영웅
  - 5~6 챕터
- **이벤트 시스템**
  - 한정 스테이지 / 한정 보상 / 한정 영입 (정책 확정 후)
- **결제 / 상점 / 운영 정책 확정**
  - 가챠 정책 / 패키지 / 시즌 패스 등은 본 단계에서 확정
  - Live2D / 일러스트 컷씬은 본 단계에서 도입 여부 결정
- **밸런싱 / 최적화 / QA**
  - 디바이스별 성능, 네트워크, 안정성 통과 기준 확정

## 6. Phase별 요약 표

| 축 | Phase 1 | Phase 2 | Phase 3 | Phase 4 |
|----|---------|---------|---------|---------|
| **전투** | 공방형 라인 디펜스 기본 (지상 2 + 공중 1, 본진 HP, 마나) | 부대 카드 UX 개선, 밸런스 1차 조정 | 전체 통합, 일일 던전 | 출시 밸런싱, 이벤트 스테이지 |
| **영웅 / 부대 카드** | 영웅 5 / 소환 5 / 슬롯 5, 직접 출격 + 슬롯 비활성화 | 영웅 10~15 / 소환 8~10, 링크·수리 정식화 | 영웅 20+, 영입 시스템 도입 (정책 결정 후) | 영웅 30+, Live2D 도입 여부 결정 |
| **영지** | 최소 (수동 부여로 대체 가능) | 기본 3~4 시설, 마나 / 육성 / 수리 연동 | 시설 확장, 자원 수급 안정 | 운영용 최종 정비 |
| **수집 / 영입** | 수동 부여 (영입 정책 결정 전) | 영입 정책 검토 / 시범 | 영입 정책 확정 + 시스템 반영 (주점 등) | 가챠 / 패키지 / 시즌 패스 등 결제 확정 |
| **데이터 / 서버** | 로컬 / 더미 데이터 허용 | 서버 1차 연동 (데이터 동기화) | 운영 가능한 서버 / 권한·검증 범위 결정 | 부하 / 안정성 / 모니터링 통과 |
| **아트 / UI** | 플레이스홀더 | 픽셀아트 1차 적용, UI 정식 도입 | UI 안정화, 이벤트 UI 추가 | 최종 폴리시, 일러스트 / Live2D(결정 시) |
| **제외 / 후순위** | 가챠 / PvP / 길드 / 이벤트 / 속성 상성 / 결제 / Live2D | PvP / 길드는 여전히 제외 권장 | 방어 전용 모드 후보, PvP / 길드는 여전히 후순위 | 결정에 따라 도입 여부 확정 |

## 7. 결정 필요

- 제조 + 방문 영웅 + 가챠 병행 여부 (영입 / 수익화 정책)
- 방어 전용 모드 / 무한 방어전 도입 시점 (Phase 3 vs Phase 4 이후 vs 보류)
- 본진 자동 공격 / 부속 시설 도입 여부 및 도입 Phase (구 "성벽 무기")
- 링크 시스템이 소환 유닛에도 적용되는 시점 (Phase 2 검증 결과 반영)
- 서버 권한 / 전투 검증 범위 (Phase 2~3 어느 시점에 클라 단독에서 서버 검증으로 전환할지)
- 주점 시스템 유지 여부 (영입 정책 결정에 종속)
- Live2D 도입 Phase

## 8. 구버전에서 격리 / 후순위화한 항목

| 구버전 표현 | 처리 |
|------------|------|
| Phase 1 "기본 전투 시스템" (모호) | 공방형 라인 디펜스 + 부대 카드 운용의 구체 항목으로 풀어 씀 (§2.2) |
| Phase 1 "링크 시스템 (1-3링크)" | 정식화는 Phase 2로 이관, Phase 1은 기초 링크 / 직접 출격 성능 반영 테스트만 (§2.3) |
| Phase 2 "성벽 무기" 확정 기능 | 본진 자동 공격 / 부속 시설 도입 여부로 일반화, 결정 필요로 격리 (§7) |
| Phase 3 "무한 방어전" 필수 기능 | 방어 전용 모드 후보로 격하, Phase 3 필수 아님 (§4.2, §7) |
| Phase 3 "주점 시스템" 확정 | 영입 / 수익화 정책 결정에 종속, 확정 표현 제거 (§4.2, §7) |
