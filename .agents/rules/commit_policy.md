# Commit Policy

## Precedence

Project commit policy overrides any tool default. Claude Code, Gemini CLI,
Codex, and any other agent CLI may carry a built-in commit-message template that
auto-appends co-author lines, model signatures, or generated-by notices. Those
defaults are explicitly overridden by this file. When the tool default and this
policy disagree, this policy wins.

## Git Repository Discovery

This agent OS may be reused in workspaces with one Git repository, nested Git
repositories, or ignored project folders. Do not assume a fixed repo layout.

Before any Git action:

1. Identify the target file paths.
2. Resolve the Git root for those paths with `git -C <path> rev-parse --show-toplevel`.
3. Compare the result with the optional repo inventory in `.agents/project/repos.md`
   when that file exists.
4. Use `git -C <repo> ...` for every command so the current shell directory cannot
   mislead the session.

Project-specific repository names, remotes, branch policy, and hook activation
commands belong in `.agents/project/repos.md`, not in this reusable policy.

## Before Commit

1. Run `git -C <repo> status` and confirm staged vs unstaged vs untracked.
2. Run `git -C <repo> diff` for unstaged changes and `git -C <repo> diff --cached`
   for staged changes.
3. Review untracked files; do not blanket-add.
4. Separate current-agent changes from pre-existing user changes; preserve the
   latter.
5. Check for sensitive files, generated files, binary replacements, and lock
   conflicts.
6. Run validation appropriate to the touched files.
7. Update progress or handoff only if the task outcome changed.
8. Confirm the commit message follows the message style and forbidden-patterns
   rules below.

## Commit Message Style

History uses conventional prefixes such as `feat:`, `fix:`, `docs:`, `chore:`,
`refactor:`, `test:`, and `build:`. Match that style. Keep the subject under
about 70 characters, wrap the body when needed, and focus on why the change was
made.

Example:

```text
docs: clarify reusable agent overlay policy
```

## Forbidden Patterns In Commit Messages

The following strings must not appear in any commit message produced by an
agent. The local `commit-msg` hook rejects commits containing them.

- `Co-Authored-By:`
- `noreply@anthropic.com`
- `Claude Opus`
- `Generated by`
- `Generated-by`
- Robot emoji or promotional tool markers

Closely related strings that agents should self-police:

- `Claude`, `Codex`, `Gemini`, `GPT-`, `gpt-`, `o1`, `Anthropic`, or `OpenAI`
  used as authorship or signing markers.
- Any "Authored by <model>", "Signed by <tool>", or "Created with <tool>" line.

Do not add generated co-author lines, model signatures, tool signatures, or
unrelated automatic text. The orchestrator session is the author of record; the
human user is the approver. No extra trailers.

## Hook Activation

A tracked `commit-msg` hook is provided under `.agents/git-hooks/commit-msg`.
Activate it per repository by pointing `core.hooksPath` at that directory.

For the repository that tracks `.agents/`, a relative hooks path is usually
appropriate:

```powershell
git -C <agent-os-repo> config core.hooksPath .agents/git-hooks
```

For nested repositories that do not track `.agents/`, use an absolute path to the
agent OS hook directory:

```powershell
git -C <project-repo> config core.hooksPath <absolute-agent-os-root>/.agents/git-hooks
```

This is a user-environment change. An agent must not run these `git config`
commands without explicit user approval. The agent's job is to document the
steps, or run them only when the user has approved that scope.

The hook reads `$1` (the commit message file) and exits non-zero if any
forbidden pattern is found, with a message that names the matched pattern. Do not
bypass it with `--no-verify`; fix the message and re-commit.

## After Commit

Report the commit hash and remaining working tree status. If the hook rejected
the commit, repair the message and re-run; do not bypass with `--no-verify`.
