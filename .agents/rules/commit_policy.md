# Commit Policy

## Precedence

**Project commit policy overrides any tool default.** Claude Code, Gemini CLI, Codex, and any other agent CLI may carry a built-in commit-message template that auto-appends co-author lines, model signatures, or generated-by notices. Those defaults are explicitly overridden by this file. When the tool default and this policy disagree, this policy wins.

## Git Locations (two repos in this tree)

This working tree contains two independent Git repositories. Always know which one you are committing to.

- **Outer (infrastructure + agent OS):** `H:\Git\Portpolio\FrontierBastion`
  - Remote: `github.com:Bo-sung/ai-workspace-template`
  - Tracks: `.agents/**`, `.shared-ai-tools/**`, entrypoint `.md` files, `.gitignore`, top-level repo configs.
  - The `Project/` directory is gitignored here.
- **Inner (game design content):** `H:\Git\Portpolio\FrontierBastion\Project\FrontierBastion_plan`
  - Remote: `github.com:Bo-sung/FrontierBastion_plan`
  - Tracks: design documents under `시스템/`, `용어 사전.md`, overview docs `01_…05_`, etc.

Standard command form, pinned with `-C` so the working directory cannot mislead:

- Outer: `git -C H:\Git\Portpolio\FrontierBastion <command>`
- Inner: `git -C H:\Git\Portpolio\FrontierBastion\Project\FrontierBastion_plan <command>`

Before any commit, confirm which repo the changes belong to and use the matching `-C` path. Mixing them is a frequent source of "missing changes" or "wrong remote pushed" mistakes.

## Before Commit

1. `git -C <repo> status` — confirm staged vs unstaged vs untracked.
2. `git -C <repo> diff` (or `--cached` for staged) — review the actual hunks.
3. Review untracked files; do not blanket-add.
4. Separate current-agent changes from pre-existing user changes; preserve the latter.
5. Check for sensitive files, generated files, binary replacements, and lock conflicts.
6. Run validation appropriate to the touched files.
7. Update progress or handoff only if the task outcome changed.
8. Confirm the commit message follows the message style and forbidden-patterns rules below.

## Commit Message Style

History uses conventional prefixes such as `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`, `build:`. Match that style. Keep the subject under ~70 chars, body wrapped, and focused on the *why* of the change.

Example:

```
docs: 에이전트 운영 체계 추가
```

## Forbidden Patterns in Commit Messages

The following strings must not appear in any commit message produced by an agent. The local `commit-msg` hook (see [Hook Activation](#hook-activation) below) rejects commits containing them.

- `Co-Authored-By:` — generated co-author trailer, in any form (case sensitive on hook side; reject case-insensitively when reviewing manually).
- `noreply@anthropic.com` — Anthropic generated email.
- `Claude Opus` — model signature.
- `Generated by` / `Generated-by` — generic AI-generated marker.
- `🤖` — robot emoji marker used by some tool templates.

Closely related strings that agents should self-police (not all hook-enforced, but policy-equivalent):

- `Claude`, `Codex`, `Gemini`, `GPT-`, `gpt-`, `o1`, `Anthropic`, `OpenAI` used as authorship/signing markers.
- `🤖 Generated with [Claude Code]` and similar promotional lines.
- Any other "Authored by <model>", "Signed by <tool>", "Created with <tool>" line.

Do not add generated co-author lines, model signatures, tool signatures, or unrelated automatic text. The orchestrator (Claude / Codex / Gemini session) is the author of record; the human user is the approver. No extra trailers.

## Hook Activation

A tracked `commit-msg` hook is provided under `.agents/git-hooks/commit-msg`. Activate per-repo by pointing `core.hooksPath` at that directory.

For the outer repo:

```
git -C H:\Git\Portpolio\FrontierBastion config core.hooksPath .agents/git-hooks
```

For the inner repo, the same hook can be reused by pointing that repo's `core.hooksPath` at the outer hooks directory using an absolute path (the inner repo does not track the outer's `.agents/`):

```
git -C H:\Git\Portpolio\FrontierBastion\Project\FrontierBastion_plan config core.hooksPath H:/Git/Portpolio/FrontierBastion/.agents/git-hooks
```

This is a user-environment change. An agent must not run these `git config` commands without explicit user approval; the agent's job is to document the steps and let the user apply them.

The hook reads `$1` (the commit message file) and exits non-zero if any forbidden pattern is found, with a message that names the matched pattern. Do not bypass it with `--no-verify` — fix the message and re-commit.

## After Commit

Report the commit hash and remaining working tree status. If the hook rejected the commit, repair the message and re-run — do not bypass with `--no-verify`.
