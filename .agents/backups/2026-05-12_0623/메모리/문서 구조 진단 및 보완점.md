# 문서 구조 진단 및 보완점

> 이 문서는 현재 기획 문서를 직접 수정하지 않고, 향후 공방전 피봇 개편 시 참고할 진단 결과를 저장한 메모입니다.

---

## 요약

현재 문서 저장소는 시스템별 문서량이 충분하고, 영지/서버/데이터 쪽은 구현 참고 자료로 쓸 수 있을 만큼 상세하다. 다만 프로젝트의 전투 정체성이 아직 한 방향으로 고정되어 있지 않다.

가장 큰 문제는 기존 문서가 **방어형 타워디펜스/명일방주식 배치형 전투**를 기준으로 작성되어 있는데, 새 방향은 **에르엘 워즈 재해석 기반 공방형 라인 디펜스 RPG**라는 점이다. 개편 시에는 전투 핵심 문서를 먼저 다시 세우고, 그 뒤 영웅/덱/재화/데이터 문서를 따라오게 해야 한다.

---

## 우선순위 높은 문제

### 1. 전투 정체성 충돌

현재 문서에는 서로 다른 전투 모델이 섞여 있다.

| 모델 | 문서 내 흔적 |
|------|-------------|
| 방어형 타워디펜스 | 성벽 내구도, 적의 성벽 도달, 무한 방어전 |
| 명일방주식 배치형 | 배치 포인트, 고정 배치 슬롯, 준비 단계 배치 |
| 에르엘 워즈식 라인 진격 | 지상 2라인 + 공중 1라인, 영웅 전선 진격 |
| 신규 피봇 방향 | 공방전, 적 본진 압박, 부대 카드 시스템 |

대표 충돌 지점:

- `시스템/스테이지 시스템.md`: 적 목표가 성벽 도달이고, 승패도 성벽 내구도 중심이다.
- `시스템/게임 모드.md`: 별 평가가 성벽 내구도 기준이다.
- `시스템/영웅 시스템.md`: 영웅은 성벽 위 원거리 공격 상태에서 전선으로 배치되는 구조다.
- `메모리/공방전 피봇 및 부대 카드 시스템.md`: 적 진지를 압박하는 공방형 라인 디펜스를 새 방향으로 잡고 있다.

개편 시 결정:

- 기본 전투 승리 조건을 `적 본진 파괴`로 바꿀지 확정한다.
- `성벽 내구도`는 플레이어 본진 HP로 남길지, 방어전 모드 전용으로 격리할지 결정한다.
- `배치 포인트` 중심 서술은 `라인 출격/소환` 중심으로 교체한다.

### 2. 덱 구조와 영웅 출격 구조가 새 방향과 맞지 않음

현재 `영웅 시스템`은 덱에 영웅을 넣고, 영웅을 직접 배치하는 구조다. 그러나 신규 방향은 덱 슬롯 하나가 `영웅 + 소환 유닛` 묶음이 되는 **부대 카드 시스템**이다.

현재 구조:

- 덱 슬롯 5개
- 덱에 넣은 영웅만 전투 배치 가능
- 영웅은 마나 비용 없이 직접 배치
- 영웅 회수/사망 쿨타임만 관리

신규 구조:

- 덱 슬롯 1개 = 영웅 + 소환 유닛
- 평상시에는 소환 유닛을 반복 출격
- 결정적 순간에는 영웅 직접 출격
- 영웅 출격 중에는 해당 슬롯 비활성화
- 이미 소환된 유닛은 유지

보완 필요 문서:

1. `시스템/영웅 시스템.md`
2. `시스템/스테이지 시스템.md`
3. `시스템/UI 설계.md`
4. `시스템/데이터 테이블.md`

신규 문서 후보:

- `시스템/덱 시스템.md`
- `시스템/부대 카드 시스템.md`
- `시스템/라인 출격 시스템.md`

### 4. 재화 명칭 충돌

공식 재화는 `은화/금화`인데 여러 문서에 `골드/보석`이 남아 있다.

문제 예시:

- `시스템/재화 시스템.md`: 은화/금화 사용
- `시스템/데이터 테이블.md`: `CUR_SILVER`, `CUR_GOLD`
- `시스템/영웅/수리 시스템.md`: 골드/보석 사용
- `시스템/영웅/육성 시스템.md`: 골드 사용
- `시스템/진행 시스템.md`: 보석/골드 사용
- `시스템/KPI 지표.md`: 골드/보석 기준

추천:

| 기존 혼용어 | 확정 용어 |
|-------------|-----------|
| 골드 | 은화 |
| 보석 | 금화 |
| 프리미엄 재화 | 금화 |

`용어 사전.md`를 기준 문서로 삼고, 모든 문서에서 용어를 통일한다.

### 5. 영입/수익화 구조 충돌

현재 영입 구조가 두 방향으로 섞여 있다.

| 방향 | 문서 |
|------|------|
| 제조 + 방문 영웅 확정 영입 | `영웅/획득 시스템.md`, `핵심 컨텐츠.md`, `재화 시스템.md` |
| 일반/프리미엄/10연차 가챠 | `수익화 모델.md` |

이 둘은 동시에 둘 수 있지만, 지금은 역할이 분명하지 않아 핵심 BM이 흐려진다.

추천 정리:

- 기본 영입: 제조
- 일일 FOMO/확정 구매: 방문 영웅
- 10연차 가챠: 도입 보류 또는 별도 이벤트/스킨/지원 계약으로 격리

초기 프로젝트 목표가 작게 완성하는 것이라면, Phase 1~MVP에서는 `제조 + 방문 영웅`만 유지하는 편이 문서와 시스템 복잡도를 줄인다.

### 7. 데이터 테이블이 신규 전투 구조를 담지 못함

현재 데이터 구조는 영웅/스킬/제조/스테이지/웨이브/영지 중심이다. 신규 구조를 구현하려면 아래 개념이 추가되어야 한다.

필요한 신규 데이터:

- `config_unit`: 소환 유닛 마스터
- `config_hero_unit`: 영웅이 사용할 기본 소환 유닛 또는 병종 연결
- `config_deck_card`: 영웅 + 소환 유닛 묶음 규칙
- `user_deck_card`: 유저의 전투 덱 슬롯
- `config_base`: 플레이어/적 본진 스펙
- `config_battle_upgrade`: 전투 중 업그레이드 항목
- `config_line`: 라인 수, 공중/지상 속성, 경로 정보

기존 `user_deck`은 `user_hero_id`만 들고 있으므로, 부대 카드 구조로 바꿀 경우 확장이 필요하다.

### 8. 링크 시스템의 역할 재정의 필요

현재 링크 시스템은 영웅 1명과 병사 여러 명이 한 부대 HP/화력을 이루는 구조다. 신규 구조에서는 링크가 다음 중 어디에 적용되는지 정해야 한다.

선택지:

1. 영웅 직접 출격 시 영웅 부대의 체력/화력 강화
2. 해당 슬롯의 소환 유닛 성능 강화
3. 영웅 직접 출격과 소환 유닛 모두에 일부 반영

추천:

- Phase 1: 링크는 영웅 직접 출격 성능에만 적용
- Phase 2: 링크 보너스 일부를 소환 유닛에도 확장

이렇게 하면 초반 구현 범위를 줄이면서도 장기 성장 확장성을 남길 수 있다.

---

### 9. 세계관이 방어전 정체성에 묶여 있음

세계관은 `변방 영주가 침공을 막는다`는 방어형 서사로 잘 정리되어 있다. 공방전으로 피봇해도 폐기할 필요는 없지만, 플레이 동기에는 보완이 필요하다.

보완 방향:

- 초반: 무너진 영지를 방어하고 재건
- 중반: 방어선을 넘어 마물 거점을 역공
- 후반: 마경의 본진/근원을 추적

즉, 세계관의 `방어선` 설정은 살리고, 전투 콘텐츠는 `방어만 하는 게임`이 아니라 `방어선에서 출발해 적 거점을 밀어내는 게임`으로 확장한다.

### 4. README 문서 상태가 과신을 유발함

README의 문서 상태는 대부분 `완료`로 되어 있다. 하지만 지금 기준에서는 `완료`라기보다 `1차 초안 완료`에 가깝다.

추천 상태 체계:

| 상태 | 의미 |
|------|------|
| Draft | 아이디어 초안 |
| Review Needed | 개편/검토 필요 |
| Canonical | 현재 기준 문서 |
| Deprecated | 구버전, 참조 금지 |
| Backlog | 나중에 적용 |

공방전 피봇 후에는 README 상태표를 이 체계로 바꾸는 것이 좋다.

### 5. 메모리/보류 문서와 본문 문서의 관계 규칙 필요

현재 새 방향은 `메모리/`에 저장되어 있고, 본문 문서에는 아직 반영하지 않았다. 이 방식은 좋지만 규칙이 필요하다.

추천 규칙:

- `메모리/`: 아직 본문에 반영하지 않은 결정/아이디어/진단
- `시스템/`: 현재 기준으로 채택된 공식 설계
- `deprecated/` 또는 `archive/`: 구버전 설계

개편이 시작되면, `메모리`의 아이디어를 본문으로 옮기고 적용 완료 여부를 메모에 표시한다.

## 결론

문서량은 충분하지만, 현재는 여러 시기의 아이디어가 한 문서군 안에 공존하고 있다. 특히 전투 정체성, 덱 구조, 영입 BM, 재화 용어가 흔들리기 때문에 바로 구현에 들어가면 구현 중 재설계가 반복될 가능성이 높다.

다음 개편의 첫 목표는 모든 문서를 고치는 것이 아니라, **공방전 기준이 되는 핵심 문서 3~5개를 Canonical 문서로 다시 세우는 것**이어야 한다.

추천 Canonical 세트:

1. `시스템/게임 개요.md`
2. `시스템/핵심 컨텐츠.md`
3. `시스템/전투 코어.md`
4. `시스템/부대 카드 시스템.md`
5. `시스템/개발 로드맵.md`
