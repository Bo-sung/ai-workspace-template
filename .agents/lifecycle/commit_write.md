# Commit Write Checklist

> Two repos in this working tree. Pick the right one before any `git` command — see `.agents/rules/commit_policy.md` "Git Locations".

1. **Pick repo:** confirm whether the changes are for the outer repo (`H:\Git\Portpolio\FrontierBastion`) or the inner repo (`H:\Git\Portpolio\FrontierBastion\Project\FrontierBastion_plan`). Use `git -C <repo>` for every command.
2. **Stage only the intended files.** No blanket `git add .` / `git add -A` — those routinely pull in sensitive or unrelated changes.
3. **Re-read `commit_policy.md` "Forbidden Patterns"** right before writing the message. Project policy overrides any tool default that wants to append `Co-Authored-By`, model signatures, robot emoji, or "Generated by" lines.
4. **Write a concise conventional commit message** (`feat:` / `fix:` / `docs:` / `chore:` / `refactor:` / `test:` / `build:`). Subject under ~70 chars; body wrapped; focus on *why*.
5. **Self-check the message** before committing:
   - No `Co-Authored-By:` line.
   - No `noreply@anthropic.com`.
   - No `Claude Opus`, `Claude`, `Codex`, `Gemini`, `OpenAI`, `Anthropic` used as a signature.
   - No `Generated by` / `Generated-by`.
   - No `🤖` or similar promotional emoji.
6. **Verify the commit-msg hook is active** in the target repo (`git -C <repo> config core.hooksPath` resolves to the hooks dir). The hook is a defense in depth; the message must already be clean before invoking it. Do not run with `--no-verify`.
7. **Create the commit** from the real Git root using `git -C <repo> commit -m "<message>"`. For multiline messages use a heredoc piped into `git commit -F -`, not a generated template that may inject signatures.
8. **Capture the commit hash** from the command output.
9. **Run `git -C <repo> status`** to confirm a clean tree (or the expected remaining changes).
10. **Report** the hash, the remaining working tree state, and which repo was committed to. If the hook rejected the message, repair it and re-commit — do not bypass.
