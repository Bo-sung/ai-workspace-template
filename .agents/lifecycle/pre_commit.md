# Pre-Commit Checklist

> Two repos in this working tree. Identify which one your changes belong to before running any git command. See `.agents/rules/commit_policy.md` "Git Locations" for the canonical paths.
>
> - Outer: `H:\Git\Portpolio\FrontierBastion` (infrastructure + agent OS)
> - Inner: `H:\Git\Portpolio\FrontierBastion\Project\FrontierBastion_plan` (design content)
>
> Use `git -C <repo>` for every command so the working directory can never mislead.

1. Run `git -C <repo> status` (and `--short --branch` for a compact view).
2. Run `git -C <repo> diff` for unstaged and `git -C <repo> diff --cached` for staged changes.
3. Review untracked files; never blanket-add.
4. Separate current-agent changes from pre-existing user changes.
5. Confirm no unrelated user changes are staged.
6. Check for sensitive files, generated files, binary replacements, and lock conflicts.
7. Run relevant validation for the touched files.
8. Confirm the commit message follows `.agents/rules/commit_policy.md`, including the forbidden-patterns list (no `Co-Authored-By:`, no model/tool signatures, no `🤖`, no `Generated by`).
9. Confirm the `commit-msg` hook is active in the target repo (`git -C <repo> config core.hooksPath` should resolve to a directory containing the commit-msg hook). If not active, document the activation command for the user; do not bypass with `--no-verify`.
