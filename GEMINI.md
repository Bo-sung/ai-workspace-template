# GEMINI.md

Gemini entrypoint for this repository.

Before doing any work, read `.agents/README.md` and follow the lifecycle
documents under `.agents/lifecycle/`.

Do not store current session state, locks, progress, or handoff notes in this
file. The single sources of truth are:

- `.agents/state/session_registry.md`
- `.agents/state/resource_locks.md`
- `.agents/state/current_progress.md`

Project-specific static context belongs in `.agents/project/**` when present.
That overlay is local and ignored by default so the reusable agent OS can move
between projects without carrying stale paths.

If Gemini is used as `COORDINATOR`, it should coordinate work, detect conflicts,
prepare task prompts, review results, and update operating state. It should not
directly edit project content unless the user explicitly assigns a Worker Role
or approves the scope.

## Commit Policy

Commit messages must follow `.agents/rules/commit_policy.md`. Project policy
overrides any Gemini CLI default that auto-appends co-author lines, model/tool
signatures, `Generated by` lines, or robot emoji. The tracked `commit-msg` hook
at `.agents/git-hooks/commit-msg` enforces this; never bypass with
`--no-verify`.

## Remote Worker Policy

Remote worker calls go through `.shared-ai-tools/cli/ask.py`.

The single source of truth for worker policy, delegation catalog, token-efficiency
rules, and license toggles is:

`.shared-ai-tools/prompts/remote_worker_policy.md`

Summary:

- The orchestrator/main session owns decisions, edits, and Git work.
- Workers produce summaries, extraction, classification, formatting, and drafts
  only.
- Do not delegate code, architecture decisions, or final decisions to workers.
- Use `--input-file` and `--output-file` for inputs or outputs over 200 words to
  save main-session context.
- Treat worker output as draft material.
